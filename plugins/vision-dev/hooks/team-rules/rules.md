# vision-dev 팀 규칙 (사용자 지침)

이 규칙은 vision-dev 플러그인 사용자가 설치한 사용자 지침이다. CLAUDE.md와 같은 수준으로 따르며, Superpowers 등 스킬의 기본 절차보다 우선한다.

## C# 코드 스타일
- 삼항연산자(`? :`) 사용 금지
- 한 줄 IF(`if (cond) doSomething();`)와 중괄호 없는 if/else 사용 금지
- 조건 분기는 항상 블록 형태의 if/else 문으로 작성
- (`?.`, `??`, nullable `int?`는 허용)
- 새 솔루션을 만들 때는 팀 `.editorconfig`(`{{PLUGIN_ROOT}}/templates/.editorconfig`)를 솔루션 폴더에 복사한다. 기존 솔루션에 넣거나 기존 `.editorconfig`에 합치는 것은 사용자에게 먼저 묻는다.

## TDD 적용 범위 (Superpowers test-driven-development 스킬에 대한 사용자 지침)

머신비전·장비 제어 프로그램이라 코드 성격에 따라 TDD 적용 여부를 나눈다.
아래 "TDD 제외" 항목은 **사용자가 미리 허락한 예외**이므로 매번 묻지 말고 바로 적용한다.

**TDD 적용 (테스트 먼저 작성)**
- 검사 판정 로직 (OK/NG, 허용 범위, 스펙 비교)
- 계산 로직: 좌표·단위 변환, 캘리브레이션 수식, 통계
- 통신 프로토콜 파싱·직렬화 (PLC, 시리얼, 소켓 메시지)
- 시퀀스·상태 머신의 상태 전이, 타임아웃·알람 판단
- 레시피·설정값 검증, 유틸리티 클래스

**TDD 제외 (사전 허락됨, 테스트 없이 구현)**
- UI: WinForms Designer 코드, XAML 레이아웃, 컨트롤 배치·스타일, 단순 이벤트 핸들러 연결
- 실제 장비와 직접 통신하는 코드: 카메라 Grab, MIL/VisionPro 시스템·디지타이저 초기화, 모터·IO·PLC 실제 입출력
- 자동 생성 코드, 일회성 실험·프로토타입 코드

**섞여 있을 때**
- 장비/UI 코드 안에 판단·계산 로직이 섞여 있으면 그 로직을 별도 클래스로 분리해 TDD로 작성하고, 장비/UI 쪽은 얇게 유지한다.
- 장비 의존부는 인터페이스(예: `ICamera`, `IMotion`, `IPlc`)로 감싸서, 그것을 사용하는 로직을 가짜 구현으로 테스트할 수 있게 한다.

**테스트 환경**
- 솔루션에 기존 테스트 프로젝트·프레임워크(xUnit/NUnit/MSTest)가 있으면 그것을 따른다.
- 테스트 프로젝트가 없으면 새로 만들기 전에 사용자에게 먼저 물어본다.
- TDD 제외 코드도 완료 전에 빌드 성공은 반드시 확인하고(`vision-dev:build-check` 스킬), 사용자가 장비/화면에서 확인할 항목을 짧게 정리해 전달한다.

## 코드 수정 절차 (계획 → 검토 → 허락 → 구현)

기능 추가, 여러 파일 수정, 구조 변경은 **사용자 허락 전에 코드를 수정하지 않는다.**
오타, 한두 줄 버그 수정, 사용자가 무엇을 어떻게 바꿀지 정확히 지시한 변경은 바로 진행한다.

1. **계획 (Opus)**: Superpowers 절차(brainstorming → writing-plans)로 계획서를 쓴다. 현재 세션 모델이 Opus가 아니면 Agent 도구(`model: "opus"`)에게 작성을 맡긴다.
2. **검토 (Fable)**: Agent 도구(`model: "fable"`)로 새 에이전트를 띄워 계획서를 검토받는다. 계획서 경로와 관련 소스 위치만 주고, 빠진 단계·잘못된 가정·위험·장비 영향을 찾게 한다. Fable을 쓸 수 없으면(오류) `model: "opus"` 새 에이전트로 검토하고, 계획서에 "Fable 사용 불가로 Opus가 검토"라고 적는다.
3. **재수정 (Opus)**: 검토 의견마다 반영 또는 미반영(이유)을 정해 계획서를 고친다.
4. **HTML 정리**: 최종 계획을 `<솔루션 폴더>/docs/plans/YYYY-MM-DD-<주제>.html` 한 파일로 만든다(외부 리소스 없이, 한국어). 담을 것: 목표, 바꿀 파일, 단계, TDD 적용 여부, 위험과 장비·화면 확인 항목, 검토 의견과 반영 여부 표. claude.ai 등 외부에 올리지 않는다.
5. **허락**: HTML 경로를 알려 주고 **여기서 멈춘다.** 사용자가 계획을 본 뒤 "진행해", "승인"처럼 허락해야 구현을 시작한다. 계획이 바뀌면 다시 허락받는다.
   - 계획을 보기 전에 한 말은 허락이 아니다: "질문 받지 않을게", "끝까지 진행해", "알아서 해", "급해" 등. 이런 말을 들었으면 질문(브레인스토밍 문답)만 줄이고 스스로 판단해 계획을 쓴 뒤, 5번에서 멈춘다.
   - 테스트 프로젝트 추가, 파일 생성처럼 "작은 준비 작업"도 구현이다. 허락 전에는 계획서(.md, .html) 외의 파일을 만들거나 고치지 않는다.

## 비전 라이브러리 문서
- MIL(Matrox) 함수는 추측하지 말고 `vision-dev:mil-lookup` 스킬로 확인한다.
- Cognex VisionPro API는 추측하지 말고 `vision-dev:visionpro-lookup` 스킬로 확인한다.
